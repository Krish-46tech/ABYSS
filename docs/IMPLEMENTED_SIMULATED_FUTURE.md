# ABYSS Implementation Status Through Phase 5

This is a scope and provenance inventory. Numerical model results have one source of truth: [METRICS.md](METRICS.md). The current detector is `improved_v2_baseline_finetune_adamw.pt`, used with baseline preprocessing at 640 px and validation-fitted `calibration_improved_v4.json`.

| Phase | Implemented and verified | Remaining limitation |
| --- | --- | --- |
| 0: project setup | Repository, Python environment/dependencies, backend and frontend project skeletons, run scripts and tests exist. | README roadmap and architecture prose still contain old weighted-fusion wording; rely on the audited status here. |
| 1: data | Raw-image ingestion, grouped train/validation/test split, baseline denoising/normalization and 640-pixel letterboxing, YOLO labels, and processed dataset summaries are implemented. | Survey-pass groups for side-scan images are filename-derived proxies, not navigation-confirmed tracks. No georeferenced ground truth or acquisition specifications were found. |
| 2: detection | YOLOv8 training/checkpoints, baseline-640 inference, held-out test evaluation, and per-class AP reporting are implemented. Checkpoint/config/hash matching is tested. | Native model still confuses some Plane and Ship instances and has weak Shipwreck AP; the filename override has been removed rather than used to conceal this. |
| 3: confidence | Shadow and image-quality features, model-specific logistic regression, validation NLL temperature scaling, v4 artifact with checkpoint hash/date/config, leakage audit, and separate raw/fused/final outputs are implemented. | Shadow/quality features are heuristics; shadow direction assumes processed-image orientation. Validation ECE is in-sample and bin-sensitive, as documented in METRICS.md. |
| 4: evaluation | Corrected held-out mAP, per-class AP, FROC/Pd, 3-way ECE and reliability plots, fixed-threshold precision/recall/F1, raw confusion matrices, PR curve, position audit, and improvement log are complete. The old enhanced-768 run is retained but marked SUPERSEDED. | FP/km, FP/km², area-based Pd, positional RMSE, and sensor specifications lack real survey/nav/acquisition inputs and are not computed. |
| 5: frontend, fast mode | React/Vite/Tailwind upload and detect, API-coordinate box overlay, separate raw/fused/calibrated confidence values, real priority ranking and breakdown, coordinate source labels, and reachable/unreachable/error states. One live held-out image and backend-down request were verified with screenshots. | No 3D view, automated browser suite, multi-image UX pass, or polished styling; these were intentionally excluded from fast mode. |

The FastAPI detection service is functional and tested against the native model output. Its geolocation algorithm uses supplied navigation metadata when provided; absent that, it returns a **simulated fallback origin**, not a measured location. Priority ranking uses explicit hand-set policy weights, not a validated hazard model. These outputs must not be described as ground-truth geolocation or learned risk probabilities.

The frontend runs on the unchanged baseline-640/v4 backend; the four bounded retrain candidates were not adopted. [Phase 5 verification screenshots and saved API response](../logs/phase5_frontend/verification.md) document the one-image check. Phase 6 and 7 have not started.
